# Neko 多 QQ 消息同步方案

## 当前可用方案：管理员截图导入

当前 NapCat 运行方式仍是“单活账号”：同一时刻只有一个 QQ_NAPCAT 配置负责实时入站和发送。为避免账号切换、端口和 Token 复用造成错收件人，管理员可用一批聊天截图补充另一账号的上下文：

1. 私聊橙蓝发送 `/neko 截图开始 联系人名称或QQ`。
2. 连续发送聊天截图，单批最多 40 张。批次期间图片会强制保存并进行本机图片文字识别，不受普通媒体保存/识别开关影响。
3. 发送 `/neko 截图结束`。Neko 优先使用 Kimi K3 整理稳定事实、偏好、关系背景、持续话题和交流习惯，并在不可用时使用现有模型链兜底。
4. 放弃本批内容时发送 `/neko 截图取消`。

每张截图只收集，不逐张回复；批次、截图附件、识别文本、实际模型和写入数量均会留存。可靠记忆直接启用，不需要审批，但仍可在后台“独立记忆 → 记忆管理中心”编辑、置顶或删除。

单条人工记忆可使用：`/neko 记住 联系人名称或QQ-需要加入的记忆`。

## 自动同步的推荐方案：双 NapCat 实例

真正同时接收管理员账号和橙蓝账号，需要两个彼此独立的 NapCat 实例，而不是在同一实例内切换登录：

- 每个实例使用独立的 QQ 登录、数据目录、HTTP Server 端口和 Access Token，例如 `127.0.0.1:3001` 与 `127.0.0.1:3002`。
- Neko 为每个账号生成独立的入站地址和 Token；入站鉴权后直接解析出固定 `account_id`，不能再依赖“当前活动账号”猜测来源。
- 出站连接器、去重键、联系人、会话、消息、记忆、待发箱和限频器都以 `account_id` 隔离。
- 后台分别显示两个实例的登录 QQ、端口、最近入站、最近发送和故障状态；任一实例离线不影响另一实例。
- 启用第二账号前，应增加“入站账号与 NapCat 当前登录 QQ 一致”校验，以及跨账号错收件人自动急停。

在上述隔离完成前，保持单活实时托管并使用截图导入，是不会因账号身份模糊而误发消息的稳妥方案。

## 管理员命令分隔符

需要把“目标”和“内容”分开的命令统一使用第一个 ASCII 连字符 `-`：

- `/neko 记住 大臭狐-喜欢研究图像识别`
- `/neko 找 大臭狐-SAM 技术的实际运用`
- `/neko 发送 大臭狐-今晚记得取外卖`
- `/neko 发送文件 大臭狐-report.pdf`
- `/neko 时段 09:00-23:30 确认`

旧的 ASCII 竖线 `|` 不再接受，系统会返回明确的迁移提示。
